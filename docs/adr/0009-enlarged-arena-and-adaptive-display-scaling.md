# 9. Enlarged Arena Geometry and Responsive Display Scaling Architecture

**Context & Decision**:
The survival arena was originally constrained to a fixed 1280x720 (40x23 tiles) boundary with an integer-locked display viewport, causing restricted mobility during late-game swarm encounters and thick letterboxing borders on non-matching monitor resolutions. We decided to expand the canonical arena geometry by 2x linearly (4x area) to 2560x1440 (80x45 tiles of 32x32) with a 4-quadrant clustered obstacle prop distribution (NW, NE, SW, SE) preserving an open central plaza for player spawn and boss combat. The display engine is transitioned to `canvas_items` mode with `expand` aspect and `fractional` scale mode, allowing seamless edge-to-edge rendering on all aspect ratios (16:9, 16:10, 21:9 Ultrawide) with margin-pinned HUD elements. Furthermore, runtime window management incorporates `DisplayModeToggle` hotkeys (F11, Alt+Enter) persisted across sessions via `SaveManager`, and camera optics adopt `DynamicBossZoom` (1.0x standard, smoothly interpolating to 0.85x during the Wave 5 Boss Giga Null encounter).

**Consequences**:
- **Benefits**: Provides expansive tactical maneuverability for kiting dense enemy swarms and dodging bullet hell patterns; completely eliminates black letterboxing bars across arbitrary resolutions; delivers dramatic cinematic scale during boss encounters while preserving pixel-crisp combat intimacy during standard waves; remembers player display mode preferences across game launches.
- **Constraints**: Viewport-aware enemy spawner and camera boundary clamps must dynamically query arena bounds (`arena.get_arena_bounds()`) rather than relying on hardcoded 1280x720 constants. Existing unit tests asserting on fixed 1280x720 extents must be updated to validate the 2560x1440 spatial extents and responsive viewport behavior.
